Technical Glossary & Definitions
A brief guide explaining deep learning and remote sensing terms for non-technical evaluators
Deep Learning Terminology
GAN (Generative Adversarial Network)
A deep learning framework consisting of two networks—a Generator that synthesizes realistic outputs (e.g. converting single-band thermal into multi-band RGB) and a Discriminator that tries to distinguish generated imagery from real imagery. They train in competition, driving high realism.
U-ViT (U-Net Vision Transformer)
A hybrid neural network architecture that combines the spatial preservation of a U-Net (using direct skip connections) with the long-range relational reasoning of a Vision Transformer (ViT), allowing the model to capture global contextual patterns across large satellite tiles.
SR (Super-Resolution)
The process of increasing the spatial resolution of an image by reconstructing high-frequency details. In this project, upscaling the coarse 200m downsampled Thermal Infrared (TIR) input back to a sharp 100m native equivalent.
mAP (Mean Average Precision)
The standard metric for evaluating object detection algorithms (such as YOLOv8). It calculates the average detection precision across various intersection-over-union (IoU) thresholds; higher mAP indicates more accurate bounding boxes and classification.
cGAN (Conditional Generative Adversarial Network)
A GAN variant where the generator is conditioned on auxiliary input (like a source image), guiding the network to produce a specific paired translation (e.g., thermal-to-optical) instead of random textures.
AdamW (Adaptive Moment Estimation with Weight Decay)
An optimization algorithm that decouples weight decay from gradient updates, stabilizing Vision Transformer and GAN training.
SGD (Stochastic Gradient Descent)
A fundamental optimization algorithm that updates network parameters iteratively using mini-batch gradients.
TTUR (Two-Time-Scale Update Rule)
A training method using different learning rates for the Generator and Discriminator to guarantee local convergence and avoid mode collapse.
Lovász-Softmax
A mathematically rigorous loss function that directly optimizes the Intersection-over-Union (IoU) segmentation metric in neural networks.
PatchGAN
A discriminator architecture that classifies N x N local patches in an image rather than producing a single global real/fake score, preserving sharp high-frequency textures.
MTL (Multi-Task Learning)
Training a single neural network to perform multiple related tasks simultaneously (e.g. upscaling and colorizing), improving representation sharing and training efficiency.
ESRGAN (Enhanced Super-Resolution GAN)
A state-of-the-art super-resolution network using Residual-in-Residual Dense Blocks (RRDB) to upscale images while maintaining sharp details without Batch Normalization artifacts.
PixelShuffle
An upscaling layer (sub-pixel convolution) that rearranges feature map channels into spatial dimensions to increase resolution efficiently.
VGG Perceptual Loss
A loss function that evaluates high-level feature similarity using activation maps of a pre-trained VGG-16 network instead of raw pixel distance.
Geospatial & Metric Reference
GEE (Google Earth Engine)
A cloud-based computing platform for large-scale environmental and geospatial data analysis, providing direct access to petabytes of historical satellite catalogs (including Landsat and Sentinel).
PSNR (Peak Signal-to-Noise Ratio)
An objective metric assessing the quality of a reconstructed or super-resolved image relative to its original. Expressed in decibels (dB) on a logarithmic scale; higher values represent lower reconstruction errors.
SSIM (Structural Similarity Index Measure)
A perception-based metric measuring structural similarity between two images. Unlike pixel-level PSNR, SSIM evaluates luminance, contrast, and structural textures, producing scores from -1 to 1 (where 1 is identical).
FID (Fréchet Inception Distance)
A visual quality metric evaluating the statistical distance between feature distributions of real images and generated ones in a deep feature space; lower values indicate higher output realism and diversity.
TIR / IR (Thermal Infrared / Infrared)
Wavelengths of the electromagnetic spectrum (typically 8–14 μm) that measure heat radiated by objects. TIR is critical for tracking soil moisture, thermal plumes, forest fires, and night activity.
CRS (Coordinate Reference System)
Geospatial metadata defining how the 2D pixels of a digital satellite image align with coordinate points on the 3D surface of the Earth, ensuring proper overlay compatibility in GIS systems like QGIS.
LST (Land Surface Temperature)
The radiative skin temperature of the Earth's surface, which is the physical temperature quantity measured by thermal infrared satellite sensors.
NDVI (Normalized Difference Vegetation Index)
A standardized index to measure green vegetation density, calculated from Red and Near-Infrared bands.
NDWI (Normalized Difference Water Index)
A satellite index used to monitor changes in surface water bodies and moisture levels, calculated from Green and Near-Infrared bands.
NIR (Near-Infrared)
Part of the electromagnetic spectrum (0.75–1.4 μm) highly reflected by chlorophyll in plants, critical for vegetation analysis.
SWIR (Shortwave Infrared)
Part of the electromagnetic spectrum (1.4–3 μm) used to detect soil/vegetation moisture.
SAR (Synthetic Aperture Radar)
An active radar imaging technique that penetrates clouds, rain, and darkness, unlike passive optical/thermal sensors.
WGS84 (World Geodetic System 1984)
The standard global geodetic coordinate reference datum used by GPS and GIS software.
UTM (Universal Transverse Mercator)
A conformal map projection system dividing the Earth into 60 zones to minimize local distortion.
GDAL (Geospatial Data Abstraction Library)
The industry-standard translator library used by GIS systems for raster and vector data formatting.
MOSDAC (Meteorological and Oceanographic Satellite Data Archival Centre)
ISRO's data portal responsible for archiving weather and climate satellite data, including INSAT-3D/3DR collections.
USGS (United States Geological Survey)
The primary scientific agency of the United States, providing the official Landsat satellite data catalog.
Bhuvan
ISRO's national geoportal providing geospatial data, visualization tools, and thematic maps of India.
INSAT-3D / 3DR
ISRO's geostationary meteorological satellites carrying 6-band Imager and 19-band Sounder payloads for atmospheric and thermal monitoring.
OLI (Operational Land Imager)
The primary optical instrument aboard Landsat 8/9 satellites capturing high-quality multispectral bands (RGB, NIR, SWIR).
TIRS (Thermal Infrared Sensor)
The thermal instrument aboard Landsat 8/9 satellites measuring longwave radiation (Band 10) to compute surface temperature.
DN (Digital Number)
Raw, unscaled integer values recorded by satellite sensors, representing received solar reflectance or emitted thermal energy.
Kelvin
The SI base unit of thermodynamic temperature. Landsat Band 10 DNs are converted to Kelvin using calibration coefficients.
QA_PIXEL
A 16-bit quality assessment band in Landsat products containing bit-packed flags to identify clouds, shadow, snow, water, and instrument issues.
GeoTIFF
An industry-standard image format incorporating geographic metadata (coordinates, map projections, CRS) as tags inside the file.
QGIS (Quantum GIS)
An open-source desktop Geographic Information System (GIS) application used to display, edit, and analyze geospatial datasets.

For geostationary verification, data is sourced from ISRO's MOSDAC (Meteorological and Oceanographic Satellite Data Archival Centre). Unlike active SAR (Synthetic Aperture Radar) systems which operate unaffected by cloud cover, passive optical and thermal sensors require strict QA_PIXEL cloud-filtering.

Mentor Preferences

The mentor established clear technical preferences that directly impact model design:

  • Physics-Based Inputs: Preprocessing must convert raw 16-bit DN (Digital Numbers) to physical Kelvin temperature, representing the physical LST (Land Surface Temperature), using official scaling factors.
  • Joint Multi-Task Architecture: Prefer a joint model that performs SR (Super-Resolution) and Colorization simultaneously in a single forward pass, sharing encoder features. Running sequential separate models is not preferred.
  • Input Bands Stack: Stack Band 2 (Blue), Band 3 (Green), Band 4 (Red), and Band 10 (TIR). Future research branches can stack NIR (Near-Infrared) and SWIR (Shortwave Infrared) bands for vegetation and moisture anomaly tracking.
How Judges Will Test (Evaluation Protocol)

The evaluation team will verify submissions through a strict downsampling-upscaling test suite:

  • Downsampling: The judges will take a test scene's native 100m TIR band and downsample it to a coarser 200m resolution.
  • Model Upscaling: Your model will take the 200m downsampled TIR band as input and must upscale (super-resolve) it back to 100m.
  • Metric Comparison: The model's super-resolved 100m IR output will be mathematically compared against the original native 100m ground truth using PSNR (Peak Signal-to-Noise Ratio) and SSIM (Structural Similarity Index Measure).
  • Metadata Check: Output rasters will be loaded into GIS software (like QGIS (Quantum Geographic Information System) or ArcGIS) to verify that the CRS (Coordinate Reference System) and affine geotransforms remain aligned in WGS84 (World Geodetic System 1984) or UTM (Universal Transverse Mercator) coordinates.
What They Expect (Deliverables & Targets)

To secure maximum scoring, the submission must deliver and achieve the following:

  • Dual Output Files: The model must produce two distinct outputs:
    • Output 1: Super-resolved Thermal IR at 100m resolution.
    • Output 2: Colorized, super-resolved RGB at 100m resolution.
  • Inference Speed Target: Inference must run in less than 3 seconds per 256x256 tile to receive bonus points for pipeline efficiency.
  • Objective Validation: Deliver a quantitative evaluation demonstrating how the colorized output benefits a downstream task (e.g. YOLOv8 object detection).
Direction & Tactical Insights
Be Realistic on Metrics

Do not claim PSNR > 28 dB or SSIM > 0.92 on Landsat 8/9. Because thermal downscaling involves sensor noise and temperature gradients, claiming higher numbers indicates data leakage or metric computation bugs, which ISRO judges will immediately flag.

Target the Bonus Points

The mentor explicitly stated that bonus points are awarded for using the model output in an underlying downstream task. We address this by running YOLOv8 detection on the colorized output to measure mAP (Mean Average Precision) improvements over raw thermal detection.

Cloud Cover Filtering

Ensure that cloud-masking is strictly implemented during preprocessing using the QA_PIXEL band. If clouds slip into training patches, the model will incorrectly learn to associate white cloud textures with cold thermal signatures, degrading FID (Fréchet Inception Distance).

Loss Function Breakdown & Parameter Tuning Guide

To perform joint super-resolution and thermal-to-optical translation, IRIS uses a combined loss function that regulates different physical and structural aspects of the generated images:
L_total = λ¹ · L_1 + λ² · L_VGG + λ³ · L_GAN + λ&sup4; · L_SEM This multi-objective loss is critical because optimizing for pixel-level similarity alone leads to blurry, physically inaccurate results. The parameters work together as a balanced system:

λ¹ · L_1 — Pixel-Level Reconstruction Loss

Core Role & Rationale: Measures the mean absolute error (MAE) pixel-by-pixel between the generated outputs and the ground-truth target bands. Enforces absolute radiometric and temperature scale alignment.
Why it is the best: Unlike Mean Squared Error (L2 loss), which penalizes larger errors quadratically and yields blurry averages, L1 loss encourages sharper spatial gradients and preserves local temperature scale coordinates.
Tuning Impact:
• Too Low (< 5): Radiometric fidelity collapses. Output temperature measurements drift away from the physical Kelvin truth.
• Too High (> 15): Over-constrains the network, forcing the model to produce blurry averages and neutralizing the high-frequency benefits of the GAN.

λ² · L_VGG — Perceptual Feature Loss

Core Role & Rationale: Extracts deep feature maps from intermediate layers of a pre-trained VGG-19 network (specifically layers conv3_3 and conv4_3) and minimizes their spatial distances.
Why it is the best: Human visual perception and downstream feature extractors (like YOLOv8) do not compare images pixel-by-pixel; they look at structural textures, shapes, and semantic edges. L_VGG optimizes for high-level texture representation.
Tuning Impact:
• Too Low (< 0.5): Outputs appear blurry and lack sharp spatial outlines, looking synthetic and flat.
• Too High (> 2.0): Risk of texture hallucination, creating artificial patterns on plain surfaces or introducing visual noise.

λ³ · L_GAN — Adversarial Contrast Loss

Core Role & Rationale: Drives competition between the generator and a PatchGAN discriminator which classifies local 70x70 image patches as real or fake.
Why it is the best: Forces the model to generate high-frequency details (micro-textures, crisp boundaries, realistic surface reflectance) that standard statistical losses fail to resolve.
Tuning Impact:
• Too Low (< 0.5): The output suffers from "blurriness", lacking photographic crispness and texture depth.
• Too High (> 2.0): Training instability and mode collapse, causing structural distortions and artifact generation.

λ&sup4; · L_SEM — Lovász-Semantic Segment Boundary Loss

Core Role & Rationale: Utilizes ESA WorldCover masks to penalize land-cover class boundary violations directly via Lovász-Softmax loss, optimizing the Intersection-over-Union (IoU) of segment shapes.
Why it is the best: Enforces physical boundary constraints: ensuring cold thermal signatures of water bodies do not "bleed" into warm urban concrete zones, thereby preserving localized satellite indices like NDVI (Normalized Difference Vegetation Index) and NDWI (Normalized Difference Water Index) across segment transitions.
Tuning Impact:
• Too Low (< 0.05): Thermal signatures leak across geographic boundaries (e.g. river edges bleed into forests).
• Too High (> 0.3): Over-restricts valid temperature variations within classes, causing artificial flattening of natural thermal gradients.

[NOTE] Note on λ numbering Your current deck goes λ¹, λ², λ³ = 1 (L_GAN), λ&sup4; — all four weights are correctly listed. This ensures that the GAN loss has an explicit coefficient of 1.0, satisfying both technical validation and design expectations.

PyTorch Dataset Class

class IRISDataset(torch.utils.data.Dataset):
    def __init__(self, patch_dir, split='train', augment=True):
        self.patches = sorted(glob(f"{patch_dir}/{split}/patch_*_ir200.npy"))
        self.augment = augment and split == 'train'

    def __len__(self):
        return len(self.patches)

    def __getitem__(self, idx):
        base = self.patches[idx].replace('_ir200.npy', '')
        ir200 = torch.from_numpy(np.load(base + '_ir200.npy')).unsqueeze(0)
        ir100 = torch.from_numpy(np.load(base + '_ir100.npy')).unsqueeze(0)
        rgb   = torch.from_numpy(np.load(base + '_rgb.npy'))
        mask  = torch.from_numpy(np.load(base + '_mask.npy'))

        if self.augment:
            # Random horizontal flip (valid for satellite — no directional meaning)
            if random.random() > 0.5:
                ir200 = torch.flip(ir200, [-1])
                ir100 = torch.flip(ir100, [-1])
                rgb   = torch.flip(rgb, [-1])
                mask  = torch.flip(mask, [-1])

        return {'ir200': ir200, 'ir100': ir100, 'rgb': rgb, 'mask': mask}

System Design — No Single Points of Failure
Every critical step has a fallback. Designed for the 30-hour grand finale environment.
[HIGH RISK] Data Loss
GEE export fails / quota exceeded
Backup: Pre-download 3 Landsat scenes from USGS EarthExplorer to Google Drive before the finale. Never depend on GEE runtime exports during competition. Cache everything locally.
[HIGH RISK] GPU Unavailable
Colab T4 disconnects during training
Backup: Checkpoint every 5 epochs with torch.save(). Keep latest .pth on Google Drive. If T4 dies, load from checkpoint on Kaggle P100 immediately. Never train without checkpointing.
[HIGH RISK] GAN Mode Collapse
Discriminator overwhelms generator
Backup: Train with AdamW (Adaptive Moment Estimation with Weight Decay) or fallback to SGD (Stochastic Gradient Descent) if weight-decay is unstable. Use TTUR (Two-Time-Scale Update Rule): generator LR (Learning Rate) = 1e-4, discriminator LR = 4e-4. If collapse detected (G loss spikes), reload last checkpoint and reduce D LR by 10×. Have Pix2Pix without GAN loss as fallback (pure L1 + VGG).
[MEDIUM RISK] Semantic Loss Instability
L_SEM causes gradient explosion
Backup: Frozen DeepLabV3+ eliminates gradients through segmentation head. Use gradient clipping: nn.utils.clip_grad_norm_(model.parameters(), 1.0). If still unstable, anneal λ₄ from 0→5 over first 10 epochs instead of starting at 5.
[MEDIUM RISK] Cloud Contamination
Unmasked clouds distort training
Backup: QA_PIXEL bit-parsing filters cloud/shadow. Visual inspection of 50 random patches before training. If cloud patches slip through, model learns "cloud = white RGB" — a harmful spurious correlation that ruins FID.
[MEDIUM RISK] Inference Tiling Artifacts
Visible seams between patches
Backup: Overlap patches by 32px during inference with Gaussian blending at edges. Alternatively, run inference on full tile at FP16 — most modern GPUs can hold a 512×512 tile in VRAM at half precision.
[LOW RISK] GeoTIFF Output Fails
CRS metadata not preserved
Backup: Always save rasterio profile at input. Re-attach at output: rasterio.open(path, 'w', **profile). Test with QGIS before submission. Never output raw numpy without CRS.
[LOW RISK] YOLO Validation Fails
No labeled detection dataset for comparison
Backup: Use DOTA dataset (aerial object detection) with thermal-like patches, or use a small hand-labeled subset of your colorized output. Even 100 labeled patches showing mAP improvement is sufficient for the bonus criterion.

Database Architecture — What Stores What & How It Connects
Four storage types, each purpose-built. Not one monolithic database.
Object Store (S3 / GDrive)
Binary Large Object Storage
Stores: Raw GeoTIFFs, .npy patch arrays, model weights (.pth), TensorRT engines (.engine), output GeoTIFFs. Why: GeoTIFFs are 50–200MB each — no relational DB handles this. S3 gives versioning and parallel download. For hackathon: Google Drive free tier works fine.
SQLite / PostgreSQL
Relational Metadata Store
Stores: Scene metadata (Landsat path/row, date, cloud%, WRS tile ID), patch manifest (patch_id → file path → scene_id → split), evaluation results (PSNR, SSIM, FID per patch). Why: enables fast patch filtering, train/val/test split reproducibility, audit trail. Schema is ~5 tables.
Redis / Memory Cache
In-Memory Fast Cache
Stores: Batch prefetch buffers during training, inference result cache (recent tile hash → RGB output), Streamlit session state. Why: DataLoader workers prefetch next batch into RAM while GPU processes current one. Eliminates I/O bottleneck at scale. For hackathon: Python dict in Streamlit session is sufficient.
MLflow / W&B (Weights & Biases)
Experiment Tracking Store
Stores: All training runs (loss curves, hyperparams, epoch metrics), model artifact registry (version 1, 2, 3...), comparison between experiments. Why: reproducibility. If a judge asks "what learning rate?" you have a logged answer. Free tier on both platforms.
DVC (Data Version Control)
Data + Model Versioning
Stores: .dvc pointer files in Git repo pointing to actual data in S3/GDrive. Ensures your dataset and model weights are reproducibly linked to the code version that produced them. `dvc repro` reruns the full pipeline. Critical for credibility claims.
PostGIS (Optional)
Geospatial Vector Store
Stores: WRS-2 tile polygons, Landsat scene footprints, output tile bounding boxes with CRS. Enables spatial queries: "find all tiles covering Odisha". Required only if you build the full dashboard with spatial filtering. PostgreSQL + PostGIS extension.

Database Suitability & Rationale

A naive monolithic database cannot scale for remote sensing pipelines due to the conflicting demands of multi-gigabyte raster files, real-world geospatial overlap queries, and high-frequency training updates. To optimize this, our architecture leverages specialized storage engines, each chosen for its physical suitability:

  • Object Store (S3 / GDrive): Specifically chosen for its capacity to handle binary large objects (BLOBs). By storing heavy 200MB raster GeoTIFF files and model parameters separately from our database indexes, we maintain high download bandwidth and prevent relational tables from bloating.
  • Relational DB (PostgreSQL / SQLite): Ideal for structured metadata. It enforces strict ACID compliance for our batch process pipelines and scene indexes (train/val/test splits). SQLite is used for lightweight local prototyping, while PostgreSQL handles scale in production.
  • Redis Memory Cache: Fits the high-throughput prefetching requirement. Prefetching data directly into RAM during training eliminates hard-drive bottlenecks, ensuring that the GPU is never starved of training batches.
  • PostGIS (Geospatial Extender): Provides native R-Tree spatial indexing. Rather than calculating coordinate boundaries in plain Python, PostGIS offloads spatial query calculations to the database server, resolving spatial overlaps (e.g., intersecting tiles in Odisha) 100x faster than standard relational queries.
  • DVC (Data Version Control): Prevents code-to-dataset drift by generating lightweight Git pointer files. It ensures that the dataset version is mathematically locked to the model code version, ensuring reproducibility.
  • MLflow / W&B (Weights & Biases): Specializes in transient logging data. It records loss trends and parameter metrics over thousands of training steps without cluttering the operational metadata store.

Why Separate SR + Colorization Runs Faster as One Model

Sequential pipeline: two forward passes, disk I/O between them, error propagation from SR artifacts amplified in colorization. Joint model: one forward pass, shared encoder features used by both heads simultaneously. This setup drastically reduces the total network parameters and FLOPS (Floating Point Operations Per Second) compared to running two distinct neural networks. Benchmarks on similar multi-task vision models show 1.8–2.2× inference speedup vs sequential equivalent. The shared encoder learns complementary features — SR focuses on edges, colorization on texture context. They're not competing, they're mutually reinforcing.

Why Downstream Object Detection (YOLO) Validation is Crucial

Standard pixel-level reconstruction metrics such as PSNR and SSIM only evaluate mathematical grid differences, which can be misleading in remote sensing. A generated image can have high PSNR but smooth out thermal boundaries, rendering it useless for object detection.

By running a pre-trained YOLO model (trained on visible RGB spectrums) on the colorized outputs, we:
• Prove Semantic Validity: Detections succeed only if the synthesized colors and spatial details match real-world class distributions (e.g. coloring rivers blue, vegetation green).
• Avoid Retraining: Leverage existing state-of-the-art visible-spectrum vision models directly on thermal data, bypassing the need to annotate millions of thermal IR training labels.
• Measure Operational Utility: Provide a direct validation metric for downstream defence and environmental intelligence applications.

import torch
import numpy as np
from skimage.metrics import peak_signal_noise_ratio, structural_similarity

def compute_psnr_ssim(pred, target):
    """
    Computes PSNR and SSIM between predicted and target images.
    
    Args:
        pred (torch.Tensor): Predicted tensor of shape [B, 3, H, W] in range [-1, 1]
        target (torch.Tensor): Ground-truth tensor of shape [B, 3, H, W] in range [-1, 1]
    Returns:
        dict: Dict containing average PSNR and SSIM across the batch
    """
    # Detach and move to CPU
    pred_np = pred.detach().cpu().numpy()
    target_np = target.detach().cpu().numpy()
    
    # Rescale from [-1, 1] to uint8 [0, 255]
    pred_uint8 = np.clip(((pred_np + 1.0) * 127.5), 0, 255).astype(np.uint8)
    target_uint8 = np.clip(((target_np + 1.0) * 127.5), 0, 255).astype(np.uint8)
    
    psnrs = []
    ssims = []
    
    # Loop over batch dimension
    for i in range(pred_uint8.shape[0]):
        # Transpose to [H, W, 3] for scikit-image
        p_img = np.transpose(pred_uint8[i], (1, 2, 0))
        t_img = np.transpose(target_uint8[i], (1, 2, 0))
        
        # Calculate peak signal-to-noise ratio
        psnr_val = peak_signal_noise_ratio(t_img, p_img, data_range=255)
        
        # Calculate structural similarity index
        ssim_val = structural_similarity(t_img, p_img, data_range=255, channel_axis=2)
        
        psnrs.append(psnr_val)
        ssims.append(ssim_val)
        
    return {
        "psnr": float(np.mean(psnrs)),
        "ssim": float(np.mean(ssims))
    }

Thermal Inversion Problem & Fix
The most common failure mode in thermal colorization. Any ISRO satellite scientist will ask this question.
The Core Problem: Seasonal Thermal Inversion Thermal IR sensors measure emitted heat (radiative temperature), not reflected optical light. Because water has a high thermal inertia, its temperature stays relatively stable throughout the day and year, while soil and concrete fluctuate wildly. In winter in North India (December), water bodies retain heat and appear warmer than frozen soil. In summer (June), water absorbs heat slowly and appears much colder than the adjacent soil/urban concrete.

A naive model trained on mixed-season data learns contradictory mappings (e.g. "warm means forest/urban in summer, but warm means water in winter") and collapses, hallucinating wrong colors seasonally.

Solution: Month-of-Year Embedding

To resolve seasonal contradictions, we embed the acquisition month as a conditioning vector in the generator. This informs the network of the seasonal context (e.g. winter vs summer) so it learns season-specific temperature-to-color mapping matrices.

import math
import torch
import torch.nn as nn

class MonthEmbedding(nn.Module):
    """
    Encodes month integers (1-12) into a continuous sinusoidal embedding space,
    then projects and expands it to match generator spatial grid dimensions.
    """
    def __init__(self, embed_dim=8):
        super().__init__()
        self.embed_dim = embed_dim
        # Project 2D sin/cos month representation into latent embedding channels
        self.proj = nn.Linear(2, embed_dim)
        
    def forward(self, month, H, W):
        """
        Args:
            month (torch.Tensor): Month integers of shape [B] (values 1 to 12)
            H, W (int): Target spatial height and width
        Returns:
            torch.Tensor: Spatial month conditioning map of shape [B, embed_dim, H, W]
        """
        B = month.shape[0]
        # Convert month to angular position on unit circle (sin/cos encoding)
        angle = (month.float() / 12.0) * 2.0 * math.pi
        sin_emb = torch.sin(angle).unsqueeze(1) # [B, 1]
        cos_emb = torch.cos(angle).unsqueeze(1) # [B, 1]
        
        month_circle = torch.cat([sin_emb, cos_emb], dim=1)  # [B, 2]
        
        # Project linear layers and expand spatially
        embed = self.proj(month_circle)  # [B, embed_dim]
        embed_map = embed.view(B, self.embed_dim, 1, 1).expand(B, self.embed_dim, H, W)
        return embed_map
